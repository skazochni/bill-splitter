# AGENTS.md

## Стек и структура
- SPA без бандлера, сборки и зависимостей: `index.html` содержит разметку, `styles.css` — стили, `app.js` — состояние, расчёты и обработчики интерфейса.
- Состояние хранится в `localStorage` под ключом `billSplitter.v1` (см. `STORAGE_KEY` в `app.js`). Сохранение дебаунсится через `scheduleSave()` (250мс).
- Режимы: `itemized` («По позициям») и `equal` («Поровну»). Режимы и валюта синхронизируются в состоянии приложения.

## Команды для разработки/проверки
В проекте нет `package.json`/`pyproject.toml`. Python окружение есть в `.venv/`.

- Локальный сервер: `.venv\Scripts\python.exe -m http.server <PORT> --bind 127.0.0.1` (запускать из корня).
- Тесты браузером (Playwright): `.venv\Scripts\python.exe tests\test_equal_mode_no_people.py`, `.venv\Scripts\python.exe tests\test_mvp_scenarios.py`, `.venv\Scripts\python.exe tests\test_summary_export.py` и `.venv\Scripts\python.exe tests\test_currency_and_item_rounding.py` (каждый сам поднимает сервер). Требуется Playwright в `.venv` и браузер. В окружении есть Edge; тесты пытаются использовать `channel="msedge"`, при неудаче падают на `chromium`.
- Ручная проверка через skill `webapp-testing`: поднимать сервер `python -m http.server` + запускать Playwright-скрипт из `.venv\Scripts\python.exe` (см. `.opencode/skills/webapp-testing/`).
- Установка браузеров Playwright при необходимости: `.venv\Scripts\python.exe -m playwright install`.
- Юнит-тесты расчётов (Node, без зависимостей): `node --test "tests/js/*.js"`.
- PWA: при изменении любого файла из precache (index.html, styles.css, calc.js, app.js, manifest.webmanifest, иконки) увеличить `CACHE_VERSION` в `sw.js`.

## Архитектурные заметки (важное)
- **«Поровну» без участников**: в `compute()` для режима `equal` итог = 0 при `people.length===0`. При удалении последнего участника в `removePerson()` `equalTotal` обнуляется и сохраняется. В `sanitize()` при загрузке из localStorage сумма «поровну» обнуляется, если нет участников — защита от старых сохранений. Не менять это поведение без регрессионных тестов.
- **Скидка, налог и чаевые в «По позициям»**: процентная скидка (0–100%) распределяется пропорционально стоимости включённых позиций с округлением минимальных денежных единиц. Налог и чаевые рассчитываются после вычета скидки и также распределяются пропорционально чистой стоимости позиций. Позиции без участников (`sharedBy` пуст) исключаются из расчёта и помечаются предупреждением.
- **Смена валюты** не использует обменные курсы: внутренние суммы пересчитываются только при изменении точности валюты (`CURRENCIES[...].digits`). Для `JPY` (digits 0) не предполагается автоматическая конвертация по курсу.
- **Сохранение** — только `localStorage`, при ошибке показывается баннер `#storageNotice`. Данные переживают перезагрузку.
- **История счетов** хранится отдельно от черновика в `localStorage` под ключом `billSplitter.history.v1`; сохраняются последние 20 снимков. Открытие снимка заменяет текущий счёт после подтверждения.

## Тестирование
- Регрессионный тест: `tests/test_equal_mode_no_people.py`. При добавлении правок в логику расчёта/состояния — гонять его. При изменении UI-идентификаторов учесть селекторы теста.
- Основные сценарии MVP: `tests/test_mvp_scenarios.py` проверяет пример счёта только для пустого черновика и защиту существующих данных, равное деление с остатком копеек, разные наборы участников/плательщиков для позиций, скидку и налог/чаевые после неё, счёт с одним плательщиком, доступную валидацию, мобильную ширину и итоговую панель, а также сохранение/восстановление/удаление истории.
- Экспорт сводки: `tests/test_summary_export.py` проверяет содержимое копирования, подтверждение операции и печатное представление.
- Округление и валюта: `tests/test_currency_and_item_rounding.py` проверяет распределение остатка позиции, форматирование суммы при смене валюты и округление для валюты без дробной части.
- Эти тесты покрывают только явно перечисленные в них сценарии. Для новых веток расчёта и поведения добавлять отдельные проверки, а не считать их покрытыми косвенно.
